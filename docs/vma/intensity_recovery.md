# SD 强度恢复与显示实验

整理日期：2026-11-22。本文记录单图实验及目前采用的数据处理方式；使用入口见 [VMA 项目说明](../../projects/vma/README.md)。

## 逆 JET 的含义

SD 底图呈现 JET 类伪彩色。当前实现假设其对应标准 OpenCV `COLORMAP_JET`：对每个像素，在 256 个色表条目中寻找 RGB 平方距离最小的条目，取其索引作为估计强度；距离相同取较小索引。

输出是单通道 uint8 PNG。该操作不同于按 RGB 加权计算亮度，但仍不能精确恢复原始点云 intensity：原始归一化、截断和实际色表参数未知，JPEG 编码也会改变颜色。背景被映射到 0 不等于观测到了物理零强度；像素直方图也不是点云逐点强度分布。

批量脚本为 [recover_sd_intensity.py](../../projects/vma/tools/recover_sd_intensity.py)，处理三类数据的原始大图，输出到各自 `origin_data/intensity_image/`，记录方法和文件哈希。当前 converter 直接裁剪这些强度大图，模型输入仍使用彩色图，强度仅按需加载用于可视化。

## 单张裁块实验

实验输入为 `/home/guyu/data/vma/sd_data/prepared/line/images/sample_1_0.jpg`。当时直接对这张 1000×1000 JPEG 反查色表，共 100 万像素，统计结果如下：

| 估计强度区间 | 像素占比 |
| --- | --- |
| 0 | 34.55% |
| 1–31 | 9.01% |
| 32–63 | 16.19% |
| 64–95 | 18.62% |
| 96–127 | 16.89% |
| 128–159 | 4.21% |
| 160–255 | 0.55% |

均值 49.46，中位数 57；95% 的像素不超过 127，99% 不超过 143。仅统计非零像素时，均值 75.56、中位数 71。零值可能包含无点云覆盖的背景，不能单凭反查结果确定有效观测掩码。

这些数值属于“对 JPEG 裁块反查”的历史实验。当前批量流程是“原始大图反查后裁剪”，避免裁块 JPEG 再编码的影响，因此数值可能略有不同，不能直接把上述统计当作当前强度 PNG 的统计。

## Log 显示实验

尝试过两种显示映射，输入均为上述估计的 0–255 索引，结果四舍五入保存为 uint8：

```text
方案一：round(255 * ln(1 + I) / ln(256))
方案二：I > 0 时 round(32 * ln(I))，I = 0 时输出 0
```

方案一把输出范围保持在 0–255；方案二不额外归一化，该样例输出范围为 0–177。两者都会提亮低强度区域，并压缩高强度差异。

目前数据准备、Dataset 和 Visualizer **均未启用 log 映射**，保存和显示的仍是逆 JET 得到的索引。Log 只是显示实验；如后续用于模型输入，应在配置中显式定义，并保持训练与推理一致。历史实验产物曾保存在 `work_dirs/vma/intensity_recovery/`，不作为数据准备流程的必需文件。

## GT 叠加中的实例长度

在 `sample_5_0` 的 line 验证裁块中，视觉上的三条纵向线对应四个 GT 实例：

| 位置 / 实例 | 裁块 y 范围 | 原始属性 |
| --- | --- | --- |
| 左上 `#0` | 158.789 → 527.148 | 白色虚线 |
| 左下 `#1` | 527.326 → 999 | 白色实线 |
| 中间 `#2` | 60.645 → 999 | 黄色虚线 |

原图标注本身的起点不同，左线还因属性变化分成两个实例；窗口裁剪只截断超出边界的部分，不把线延长到边界。因此长度不同不代表绘图或 converter 出错。当前 Visualizer 都用连续折线连接顶点，类别决定颜色，虚实线属性不会自动改变线型；可用 `--draw-attributes` 查看属性。
